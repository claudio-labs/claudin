**Decision:** Claudin's MCP client and `mcp serve` move to `@modelcontextprotocol/client`/`server`/`core` 2.4.0 and
speak 2026-07-28 where a server offers it (branch `feat/mcp-2026-07-28`, plan `.claudin/plans/clever-foraging-engelbart.md`).
- **Order (user's call, second "está elegante?" round):** cover suites → red repro commit → migration with the
  legacy wire byte-identical → fix only what stayed red on v2 → features. The fixes were not written on 1.x
  first, because the migration would have rewritten them (the serve handler's signature, the provider's `ctx.issuer`).
- **Negotiation:** `auto` on http AND stdio. The verdict is cached on disk (`<config home>/mcp-era-cache.json`;
  modern: discover `ttlMs` clamped 1–24 h, legacy 24 h) and replayed with `connect(t, {prior})`, so the stdio
  sibling probe (two spawns) only happens on a cache miss. The probe gets `min(5 s, startup)`. A 5xx or a
  timed-out probe reconnects as 2025-11-25 on a fresh transport (Spring AI answers 500). sse/ws/ide/sdk/claudeai-proxy
  stay legacy.
- **Config:** per server `protocol: 'auto'|'legacy'` and `extensions: {skills?, tasks?, events?}` (on by default).
  The only global switch is `MCP_PROTOCOL_NEGOTIATION=legacy`, Claude Code's name. It turns tasks and events off
  too, since both exist only in 2026-07-28.
- **Wire:** a pre-connect `onmessage` hook plus a `send` wrapper on the transport instance, driven by a rule table.
  It checks list entries one by one, fills `ttlMs`/`cacheScope`/`resultType`, strips `outputSchema` (Claudin never
  enforced structuredContent; Portainer violates its own schema), cuts cursor cycles, rewrites the 2025 `initialize`
  capabilities to exactly `{roots:{}, elicitation:{}}`, and turns a `resultType:'task'` reply into a marker.
  Lists come from the SDK's `listTools()` and friends.
- **Auth:** v2 does RFC 9207 `iss`, `application_type` and the per-issuer stamps. Claudin passes `iss` from the
  callback and detects a moved authorization server in the provider. It keeps a static `Authorization` header
  over stored tokens, as 1.x did. `prompt=consent` with `offline_access` is kept, as the SDK and Claude Code do.
- **Features (all four extras taken, then Skills + Events too):**
  - URL elicitation on modern connections only.
  - Completions for MCP prompt arguments only (Claude Code completes resource templates, which was not chosen).
  - Resource-change notice: subscribe on read or @-mention, one tail line, 50 URIs per server. Claude Code has none.
  - TTL refresh at turn start: 60 s floor, replaced only on a hash change.
  - Tasks: polled inline for `min(120 s, toolTimeout)` (`MCP_TASK_INLINE_MS` in `taskPoll.ts`), then handed
    to a background `monitor_mcp` task on the main thread; `tasks/cancel` on stop and at exit. 120 s is a fixed
    number, the user's. It is NOT the Agent's `getAutoBackgroundMs()`, which is 0 unless
    `CLAUDIN_AUTO_BACKGROUND_TASKS` is set. Where nothing can run in the background (sub-agent, `-p`), the poll
    ends at the tool timeout with `tasks/cancel` and the normal timeout error. A task's `roots/list` input gets
    the connection's roots (`listRootsResult()`). Any other input method Claudin does not support (sampling…)
    cancels the task with a tool error naming it, so nothing waits out the ttl.
  - Events: model-driven through Monitor's `mcp_event: {server, event, args?}` source (one optional schema
    field, ~+220 tokens when Monitor is loaded). ListMcpResources lists the event types, so no new tool.
    Push streams keep a heartbeat watchdog (3× `heartbeatMs`) and resume from the cursor. Types without push
    are polled (1 s floor, `truncated` reported as a possible gap). Each event is a task-notification marked
    untrusted, under Monitor's 2 KB, flood and timeout caps. Like a `ws` monitor, it always asks permission.
    A type that lists no `delivery` is treated as push, and an error notification fails the task.
  - Both Tasks and Events live on the existing `monitor_mcp` task type, kinds `call`/`events`.
  - MCP Skills: on by default with a per-server opt-out, `allowed-tools` ignored, SKILL.md read on invocation
    (digest and size verified), ReadMcpResource refuses files outside the skill's manifest. Its frontmatter
    `hooks` are dropped too, so a remote server cannot register hooks that run shell on the user's machine.

**Why:** SDK 1.32.2 is the last 1.x and tops out at 2025-11-25; v1 fixes end ~2027-01. Claude Code 2.1.332 already
negotiates 2026-07-28 by default. The user asked for the newest protocol, extensions included ("vamos estar na
última versão do protocolo?").

**What changes for a teammate:**
- A new MCP wire quirk goes in `wireRules.ts` as a rule, not in an SDK patch.
- A per-era difference needs its own test on both eras (`src/mcp/__testutils__/eraServers.ts`).
- Tests that connect must keep the era cache off or point it at a temp dir (`setEraCacheDirForTests`).
- `@modelcontextprotocol/sdk` survives only as a devDependency for legacy-server fixtures, enforced by
  `src/__tests__/mcpSdkV1TestOnly.test.ts`.
- SDK facts this rests on: [[mcp-sdk-v2-verified-behaviors]].

**Rejected:**
- stdio legacy by default (chosen first, reversed once the era cache made the double spawn a once-per-TTL cost).
- A `bun patch` of the SDK as opencode did: re-applied on every bump, and opencode patched tools only.
- A separate `mcp_task` type: it would have needed new arms in two React Compiler `.tsx` files that `monitor_mcp`
  already has.
- `CLAUDIN_MCP_TASKS`: redundant with `MCP_PROTOCOL_NEGOTIATION=legacy`.
- The Events webhook: a CLI has no https endpoint.
- sampling, logging/setLevel and roots `listChanged`: deprecated or removed in 2026-07-28.
- Tying the task inline window to `getAutoBackgroundMs()`. It is opt-in and 0 by default, so out of the box
  the window became the 5-minute tool timeout. The planning question had wrongly described that 120 s timer
  as always on, and the user's answer named the number.
- Enforcing outputSchema.
- Stripping `prompt=consent`.
