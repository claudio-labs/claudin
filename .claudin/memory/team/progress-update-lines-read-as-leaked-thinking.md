Reported 2026-09-25 as "está vazando thinking": a dim `∴ Model resolution is working correctly, … I'll make that rule explicit.` line above a tool call. It is not reasoning.

- Under `thinking.display: "updates"` (interactive, real first-party endpoint, Claude 5 family — `src/providers/shims/claude/thinkingDisplay.ts`) reasoning blocks arrive **empty**. The only text a thinking block carries is a progress update, and the API labels it in the signature (protobuf 2 → 1 → 8 = `"narration"`). Session `9814f902`: 137 `thinking`-kind blocks, all empty; 5 `narration` blocks with text, all addressed to the user (one in pt-BR asking for decisions).
- The model writes updates whatever the display: headless (`"omitted"`) transcripts carry `narration` blocks too, just empty. The display decides what comes back, never what is generated.
- #238 drew them as `∴` + dim markdown; `∴` is also the `∴ Thinking` glyph, hence the "leak" reading. Since 2026-09-25 (branch `worktree-thinking-leak`) they are drawn as Claude Code 2.1.281 does: `●` + normal text, a dim ` · summarized` on every model but Opus 5.5 (CC hides it via `quizzical_shore`, granted by `opus_5_5_prompt_bundle`, which only Opus 5.5's catalog entry has), and an update breaks a collapsed read/search group instead of waiting behind it. Probes: `scripts/migrations/probes/progressUpdateRender.json`.

**Cache: display is neutral, "summarized" included** (the user remembered summaries breaking it). `session-cache-ab.ts --proxy`, Opus 5.5 @ medium, N=3 per arm, 2026-09-25 (`/tmp/session-cache-ab/20260925-034359`, gone after a reboot): omitted / updates / summarized all at 0 cache breaks, 0 lost prefix tokens, 100% resume read-back, cost $1.08 / $1.06 / $1.11 (overlap); the proxy confirmed each arm's `display` on every request, and the summarized history carried reasoning text on every turn. Real sessions agree: over 7 interactive sessions, 0 of 69 first read-backs of an update with text lost the prefix (base rate 0.6%). Not measured: switching the display mid-session (e.g. toggling `showThinkingSummaries`, then resuming).

**Sub-agent thinking, same branch:** regular sub-agents ran with `thinkingConfig: {type:'disabled'}` ("to control output token costs"), which sends no `thinking` field — and Opus 5.5 thinks anyway, at the server default, display omitted (Sonnet 5 too: 67 of 137 messages of its sub-agents after #247 held thinking with no field sent). Now a sub-agent on a model with effort (`modelSupportsEffort`) inherits the parent's config, as Claude Code's `X_o` does (`src/tools/AgentTool/subagentThinking.ts`; `CLAUDIN_DISABLE_SUBAGENT_THINKING=1` restores off). `scripts/bench/ab/subagent-thinking-ab.ts`, N=3, 3/3 correct per arm, same 5 API calls: Opus 5.5 off still counted 24–72 thinking tokens with no field sent, child $0.0544 → $0.0543; Sonnet 4.6 (where off really is off) 0 → 22 thinking tokens, child $0.0273 → $0.0268, all ranges overlapping. The task is small (3 child calls); a long Sonnet 4.6 / Opus 4.x sub-agent is the case that could cost more. No run wrote a progress update, so a sub-agent's update has not been seen rendered yet — the proxy shows the `adaptive/updates` field on every child request. The wire only changes on the Anthropic-native transports (first-party, Bedrock, Vertex, Foundry, Copilot running Claude; `"updates"` on first-party alone). OpenAI-shim models never get a `thinking` field — `modelSupportsThinking` is false for non-Claude names — and their reasoning rides `reasoning_effort`, which sub-agents already sent; DeepSeek, the one shim branch that reads `thinking`, is outside `modelSupportsEffort` and stays off.

**How to apply:** for the next "thinking is leaking" report, decode the signature kind of every text-bearing thinking block in the session `.jsonl` before touching the renderer — reasoning text under "updates" would be a real API/config bug; narration is expected. Workarounds for a user who wants none of these lines: `CLAUDIN_DISABLE_THINKING_DISPLAY_UPDATES=1` or `CLAUDIN_THINKING_DISPLAY=omitted`.
