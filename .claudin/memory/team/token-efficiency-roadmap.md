Roadmap of token-efficiency feature ideas, ranked by ROI. Verdicts from a 7-agent research pass on 2026-06-27, each grounded against the real Claudin codebase (not generic advice).

**Why:** decides what's worth building next for token savings, and records the codebase-specific reasons several plausible-sounding features are NOT worth it (premise already covered, conflicts with cache, bundle/native constraints) — so we don't relitigate them.

**How to apply:** when picking the next token-efficiency task, start at the top of the BUILD list. If asked to build a SKIP item, surface the recorded reason first.

### Batch 2 — SmartCrusher port (2026-06-29) — #7 MERGED (#93), #6 MERGED (#94, `c13d67aa`)
From comparing headroom's `SmartCrusher` (Rust port at `../headroom/crates/headroom-core/src/transforms/smart_crusher/`) against our `jsonArrayCompress.ts`. Three integration facts decide the verdicts and MUST be respected by any implementation:
- **Call sites:** `compressJsonArray` runs only in `toolResultSummarizer.ts:214` (Bash output ≥8KB, `BASH_SUMMARIZE_THRESHOLD`) and via `maybeJsonStructural` (Agent/MCP array content ≥8KB). **Input universe = JSON from shell commands** (`gh ... --json`, `kubectl get -o json`, `npm audit --json`, `aws`, test-runner `--json`) + MCP JSON. Not arbitrary text.
- **No query/context at the call site:** `maybeSummarizeToolResult(block, toolName)` (`:125`) is pure + stateless — no user message, must stay ink-free/bun-test-loadable. This kills relevance/BM25/TOIN-anchor pinning here (see SKIP).
- **Reversibility is by INDEX, not by keep-set:** the persisted backing is `jc.jsonl` = the **full** array, one element per line aligned to `#N` (`toolResultStorage.ts:316-317`); retrieval is Read offset/limit + Grep on the filepath. So **which rows we render is independent of recoverability** — changing the keep-set never makes a row unrecoverable. This de-risks content-aware selection entirely.
- **Baseline already captured the VOLUME:** the dumb head40/tail10 window (`jsonArrayCompress.ts:21-23`) already nets ~7.5% median cost ($0.64→$0.59 20-turn, $0.99→$0.86 30-turn; `scripts/profile/json-compression-*.txt`). So Batch 2's gain is mostly **correctness** (stop dropping the salient row → fewer Read-back round-trips), not raw volume.

## SKIP (não compensa) — with the recorded reason
- **Code compression with tree-sitter** (L/XL): no tree-sitter dep; WASM + grammars fight the single-file bundle. Use `scanSymbols.ts` instead.
- **ML prose compression (Kompress-style)** (XL): ONNX model in the bundle — exactly what the repo rejects.
- **Effort routing** (lower reasoning on mechanical turns): per-turn effort is only dynamic on the Anthropic path (`streaming.ts:731`); `openaiShim` binds `reasoningEffort` at construction. Misclassifying an error/failed-test turn would dumb down the analysis. Defer.
- **Semantic/vector memory (HNSW)**: false premise — Claudin already does LLM-ranked retrieval (`findRelevantMemories.ts:39` asks Sonnet for top-5). Scale is tiny (~51 files/37KB; vectors pay off at 10k+ docs). Native deps are bundle-stubbed; embeddings would need phone-home (privacy conflict).
- **Cross-agent memory** (share with Codex/Gemini): scope creep — the `team/` dir already covers the real case.
- **Relevance context fitting (BM25+embeddings)**: conflicts with the cache — per-turn relevance reorder breaks the clip-frontier (invalidates the prefix). Only viable niche is BM25 selection *inside* `/compact` (M), low payoff.
- **Image compression**: already exists — `sharp` + `imageResizer.ts` (dimension cap + JPEG quality ladder). ML version (SigLIP) is XL for a cold path (code CLI rarely sees images).
- **Live dashboard with confidence intervals** (XL): without measured ground-truth the CIs are fabricated precision; terminal ≠ proxy+web-UI. The correct form is the `/usage` line (#3).
- **SmartCrusher crushability decision tree (full)** (`analyzer.rs:421`): its point is avoiding irrecoverable lossy drops; for us the index-based `jc.jsonl` already makes every drop recoverable, so the tree is mostly moot. Only the "don't sample a high-uniqueness unique-entity array → keep all rows factored" heuristic is marginally useful (avoids Read-back round-trips) — fold that one rule into #6, skip the rest.
- **Field-role detection (ID/score)** (`field_detect.rs`): score-field only feeds the `TopN` strategy (ranked search results) — rare in shell JSON; ID-field only feeds the crushability tree (skipped above). Low hit-rate. Skip.
- **Pattern classifier + per-pattern strategy** (`classify_array`/`select_strategy`, time_series/logs/search_results/generic): the only useful sub-strategy is cluster-dedup for repetitive log arrays, which overlaps our existing Bash `collapseIdenticalRuns`/`collapseDigitTemplates`. Skip the classifier.
- **SmartCrusher relevance/BM25/embedding anchors + TOIN `preserve_fields`** (`relevance/`, `planning.rs` query signals): **blocked** — no query/context at the summarizer call site (`toolResultSummarizer.ts:125` is pure+stateless); threading the user's turn down through `toolResultStorage`→summarizer fights the module's ink-free/bun-loadable design, and embeddings add a model/native dep (bundle conflict). Consistent with the existing BM25 SKIP above. Revisit only if #6/#7 prove out and someone wants a separate query-plumbing initiative.

**DEFER (not skip): SmartCrusher lossless-first compaction** (`compaction/` — CSV+schema formatter, dotted-column flattening of nested-uniform objects, stringified-JSON-cell sub-tables). Real volume upside on `gh`/`aws` nested JSON, but it's a larger rewrite of our renderer and our flat tab-grid already captures the bulk. Revisit after #6 + #7 land.
