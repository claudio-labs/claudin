# Feature 6.1 — Command-aware Bash Output Filter

Claudin intercepts every Bash tool result before it reaches the model and removes noise — progress bars, download lines, verbose headers, passing test lines — while preserving errors, warnings, and actionable output. The filter is **on by default** for all new installations.

## Why it matters

Every token sent to the model costs money and consumes context window. Most CLI tools are chatty by design (they're built for humans, not LLMs). The filter collapses that noise silently, session after session, without you having to think about it.

Measured across a typical 30-minute session:

- **~50 000 tokens saved**
- **~72% reduction in input cost**

## Gain per command

| Command | Reduction |
|---|---|
| `bundle install` | 96% |
| `pytest` | 95% |
| `ps aux` | 93% |
| `git log` (rewritten to `--oneline`) | 92% |
| `rubocop` | 83% |
| `ls -la` | 81% |
| `go test -v` | 82% |
| `rspec` | 73% |
| `wget` | 72% |
| `cargo check` | 64% |

Beyond plain filtering, some commands are **rewritten** before they run so they produce less output structurally:

| Command | Rewrite applied |
|---|---|
| `git log` | Forces `--oneline` |
| `git status` | Forces `--porcelain` |
| `gh pr list` / `gh issue list` / `gh run list` | Forces `--json` (compact) |

## How to toggle

Open `/config` inside the Claudin REPL and look for **Bash output filter**. Toggle it on or off — the change takes effect immediately, no restart needed.

You can also set it directly in `~/.claudin/settings.json`:

```json
{
  "bashOutputFilterEnabled": false
}
```

Set to `false` to disable, omit the key (or set `true`) to enable.

## User-defined filters

You can add your own rules on top of the built-in ones. Create `~/.claudin/filters.json`:

```json
[
  {
    "command": "my-tool",
    "stripLines": ["^Fetching ", "^Resolving "],
    "collapseBlocks": [{ "start": "^--- verbose ---$", "end": "^--- end ---$" }]
  }
]
```

Filters are validated against a zod schema on load. Regex patterns are guarded against ReDoS (length cap + denylist).

## Architecture (brief)

The filter lives in `src/tools/shared/outputFilter/Bash/` and touches the rest of the codebase in exactly three places:

1. `BashTool.tsx` — `planFilter` is called before `runShellCommand`; `applyFilterToStdout` is called on the result
2. `toolResultSummarizer.ts:242` — recognises filter markers so already-filtered output is not double-processed
3. `config.ts` — registers the three config keys for `/config` integration
