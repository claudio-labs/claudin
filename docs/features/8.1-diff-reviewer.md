# 8.1 — Diff Reviewer (tabbed, split-pane `/diff`)

**Status:** shipped. This doc describes the implemented `/diff` reviewer; see the
"As-built deltas" section at the end for where the implementation refined the original study.

A redesign of `/diff` from today's single-column "list ↔ detail" overlay into an IDE-like
reviewer with **two tabs** and a **side-by-side** layout:

1. **Local Changes** — file **tree** (left) | diff of the selected file (right), collapsed to the
   changed lines with incremental expand of unchanged context.
2. **Log** — the git **graph/tree** (left) | files changed in the selected commit (right).

## File tree (Local Changes)

The left pane is a collapsible folder tree (`fileTree.ts` → `buildTreeRows`), not a flat list:

- Files are nested under their directories; folders are sorted first, then files (by basename).
  Single-child directory chains are compacted into one row (`components/diff`) like VS Code's
  compact folders. Per-repo group headers appear only when more than one repo is in scope.
- Folder rows show a caret (`▾`/`▸`) + open/closed Nerd Font folder glyph (`fileIcons.FOLDER_OPEN_ICON`
  /`FOLDER_ICON`, gated on `hasNerdFontGlyphs()`); file rows show only the basename (the tree carries
  the path) + the per-file `+/−` stat. **Group headers are collapsible too** — same caret, keyed by
  the repo `root` (no NUL, so it never clashes with a dir key); collapsing hides that repo's entire
  subtree but keeps the header. A selected header brightens + shows the pointer (it carries nested
  swatch/branch colors, so it stays non-inverse). When headers are shown, each repo's file/dir rows
  are indented one level (`baseDepth = 1`) so they line up beneath the header's name; the single-repo
  view stays flush at depth 0.
- Selection (`selectedIndex`) indexes the visible `TreeRow[]`; `selected` is non-null only on a file
  row. `collapsedDirs: Set<string>` is keyed `root\0relPath` for folders and bare `root` for group
  headers (stable across rebuilds, so toggling round-trips). On open / source change, selection lands
  on the first file row.
- Keys: `↑/↓` move; `Enter` toggles a folder/group or opens a file (focus diff); `→` expands a
  collapsed folder/group or focuses the diff on a file; `←` collapses an expanded folder/group or
  focuses the list. Dir and group rows share one `collapsibleRow` path in the handlers.
- The selected file's `+N −N` (or `binary`/`large`) is rendered **right-aligned on the diff pane's
  top border** via a second `borderText` item (`statsBorderText`, ANSI-coloured with chalk). The
  `untracked` label was removed from file rows.

Pure tree logic lives in `fileTree.ts` (no React/ink imports) so it is unit-testable
(`fileTree.test.ts`) — importing the `.tsx` would pull in `ink.js` → the build-time-stubbed
analytics module, which is unresolvable under the test/`bun -e` runner.

It also adds: per-turn diffs + stashes as selectable sources, multi-repo grouping, Nerd-Font
file icons (with fallback), and a `gg` shortcut alongside `/diff`.

---

## The problem

`/diff` today (`src/vcs/diff/ui/DiffDialog.tsx:55`) works, but it is cramped against how a
review actually flows:

| Today | Friction |
|---|---|
| `viewMode: 'list' \| 'detail'` — full-width, **mutually exclusive** | You lose the file list the moment you open a file; comparing "where am I in the tree" vs "what changed" means bouncing back and forth. |
| Detail view renders **all** hunks, **no scroll**, capped at 400 lines (`MAX_LINES_PER_FILE` in `src/vcs/diff/hooks/useDiffData.ts`) | Long files are truncated; you cannot page through them. |
| Hunks arrive pre-trimmed to 3 context lines, **no expand** | You can't pull in surrounding context to understand a change without leaving the tool. |
| Only the **ambient repo** is diffed (`gitDiff.ts:49`, no `cwd` arg) | In a workspace with multiple repos (monorepo siblings / `/add-dir`), you can't tell *which* repo's changes you're looking at, and you can't see the others. |
| No history view | There is no way to inspect what landed in recent commits without dropping to a shell. |

The source selector that already exists (working tree + one diff per agent turn, cycled with
←/→, `DiffDialog.tsx:75-83`) is a good idea hidden behind a single key with no room to grow.

## What it does

### Two tabs, side by side

```
┌ Diff ─────────────────────────────────────────────────────────┐
│  Local Changes   Log                         (Tab to switch)   │
│  source: working tree ▾   (←/→ when focus on list, only here)  │
│ ┌ Files ─────────────┐┌ Diff: src/foo.ts ───────────────────┐ │
│ │ web  2 files · main ││  12  export function foo() {        │ │
│ │› src/foo.ts  +12 -3 ││ ··· 8 lines ───────────────────────  │ │
│ │  README.md   +4  -4 ││ -18  const x = old()               │ │
│ │ api  1 file  · dev  ││ +18  const x = new()               │ │
│ │  src/bar.ts  +1  -0 ││                                     │ │
│ └────────────────────┘└─────────────────────────────────────┘ │
│  Tab tabs · ↑/↓ files · → diff · ← back · r refresh · Esc close│
└────────────────────────────────────────────────────────────────┘
```

```
┌ Diff ─────────────────────────────────────────────────────────┐
│  Local Changes   Log                         (Tab to switch)   │
│ ┌ Log ───────────────────────┐┌ Files in dca77a5 ───────────┐ │
│ │ ○ feat: @-mention nav  main ││  src/components/x.tsx  +20 -4│ │
│ │ ●  chore: bump deps         ││  src/hooks/y.ts        +3  -1│ │
│ │ ├─╮ Merge branch 'fix'      ││                              │ │
│ │ │ ● fix(ink): vacated rows  ││                              │ │
│ │ ●─╯ feat(bridge): remote    ││                              │ │
│ └────────────────────────────┘└──────────────────────────────┘ │
│  main ⟳ ⊗0 ⚠12     Tab tabs · ↑/↓ commits · → files · Esc close │
└────────────────────────────────────────────────────────────────┘
```

The Log left rail is the **real branch/merge topology** (`git log --graph`), not a flat list of
dots.

### Navigation

| Key | Action |
|---|---|
| `Tab` | switch tabs (Local Changes ↔ Log) |
| `↑/↓` | move selection in the left list (list focus) / scroll the diff (content focus) |
| `←/→` | move focus between the left list and the right pane (`←` also collapses, `→` expands a folder on Local Changes) |
| `[` / `]` | cycle the **source** selector (Local Changes) or the **project** (Log, monorepo) |
| `Enter` | open a file / toggle a folder (list focus); grow the next collapsed gap (content focus) |
| `PgUp/PgDn`, `g`/`G` | (right pane focused, split Local Changes) page / jump to ends |
| `a` | expand the whole file (Local Changes) |
| `r` | manual refresh |
| `Esc` | close (from content focus, returns to the list first) |

### Entry points

- **`/diff`** stays the canonical command (`src/commands/diff/`).
- **`gg`** opens the same overlay — but only when the prompt is **empty** (vim-style), so it
  never fires mid-typing. Note: `ctrl+g` is already bound to `chat:externalEditor`
  (`src/terminal/keybindings/defaultBindings.ts:87`), so `gg` is a prompt-empty sequence, not a global
  ctrl chord.

## The four sources (Local Changes)

The existing source selector grows from "working tree + turns" to three kinds, cycled with ←/→
while the list has focus:

1. **Working tree** — uncommitted changes vs `HEAD` (today's default).
2. **Per-turn** — one entry per agent turn (`useTurnDiffs`, `src/vcs/diff/hooks/useTurnDiffs.ts`), kept
   as-is, just folded into this tab.
3. **Stash** — `stash@{0}`…`stash@{n}` from `git stash list`; selecting one shows its files +
   diff in the same panes (diff via `git stash show -p stash@{n}`, parsed with the existing
   `parseGitDiff`).

All three feed the same left file-list + right collapsible-diff panes.

## Multi-repo / monorepo grouping

When more than one git repo is in scope, the Local Changes file list is **grouped per project**
with a non-selectable header so you always know which repo a change belongs to:

```
web   2 files changed · main
  src/foo.ts   +12 -3
  README.md    +4  -4
api   1 file changed  · dev
  src/bar.ts   +1  -0
```

- **Scope** = the unique canonical git roots of: the cwd (`findCanonicalGitRoot()`,
  `src/vcs/git/git.ts:195`), each `/add-dir` workspace directory
  (`ToolUseContext.toolPermissionContext.additionalWorkingDirectories`, `src/tools/Tool.ts:139`), and
  **nested child repos discovered under those bases** (`findNestedGitRoots`, below). Dedupe by
  canonical path; explicit roots first (cwd repo stays group #0), discovered repos after, sorted
  by name.
- **Header** = a per-repo colored Nerd-Font square swatch (`entityColorByIndex`, so siblings never
  share a color) + `basename(root)` + file count + a branch glyph () + the repo's branch
  (`getBranch()` run in that root). Glyphs degrade to a plain `· branch` separator on non-Nerd
  terminals.
- **Single repo** → no header, flat list (today's look). `↑/↓` walk the flat sequence; header
  rows are skipped.

### Nested-repo discovery (monorepo of independent repos)

The common monorepo case: the cwd holds sibling folders (`business/`, `aargau-app/`) that each
carry their **own** `.git`, so the parent's `git status` never reports their changes — and the
parent may not even be a git repo itself. `findNestedGitRoots(baseDir)` (`src/vcs/git/git.ts`,
async, unit-tested) walks the base's subtree and returns every directory with its own `.git`
(directory **or** file → submodule/worktree), canonicalized through worktree resolution.

- **Bounded & fail-open**: descends ≤ `maxDepth` (3) levels, inspects ≤ `maxDirs` (1500)
  directories, and never descends into a repo once found, into dot-dirs, or into noise dirs
  (`node_modules`, `target`, `dist`, `vendor`, …). Returns `[]` on any error.
- **Wiring**: `useWorkspaceDiff(roots, scanBases)` runs the scan per base in parallel with the
  explicit roots, merges + dedupes, diffs each as its own `RepoGroup`, and exposes the effective
  root list. `DiffDialog` derives `noRepo` from "scan settled with zero groups" (not "no explicit
  root"), and falls back to the first discovered repo for the Log/stash tabs when the cwd is a
  bare container.

## Collapse / expand (Local Changes diff)

The right pane shows only changed lines plus 3 lines of context; unchanged stretches collapse to
a marker:

```
··· 8 lines ───────────────────────
```

- Build a render model = ordered `{kind: 'hunk' | 'gap', …}` list; gaps between consecutive
  hunks and at the file head/tail become `··· N lines` markers.
- Each activation on a marker reveals **±10 more lines** (GitHub-style), pulled from the
  working-tree file text (`readFileSafe`, already used in `src/vcs/diff/ui/DiffDialog.tsx`).
- **Fail-open**: if the file content is unavailable (binary / large), keep today's behavior —
  no markers, show the existing placeholder.

### Untracked (new) files → all-green diff

`git diff HEAD` omits untracked files, so they arrive with **no hunks**. Rather than the old
"New file not yet staged." placeholder, the reviewer reads the working-tree file and synthesizes a
single all-added hunk (`gitDiff.buildAddedFileHunks` — every line `+`-prefixed, numbered from 1,
capped at the 400-line per-file limit), which renders green through the normal `ColorDiff` path
(syntax-highlighted, with the file content still passed to `renderDiffRows` for highlighting while
`undefined` is passed to `buildDiffRenderModel` so there's no spurious trailing context). The
synthesized line count is shown as `+N` in the diff pane title (the file list carries no count for
untracked files). Guards: content with a NUL byte in the first 8 KB is treated as binary
(`fetchUntrackedFiles` can't detect binary) and unreadable/empty new files fall back to the
"New file not yet staged." message.

## Nerd-Font file icons (with fallback)

A `glyphs` helper resolves once via `hasNerdFontGlyphs()` (`src/terminal/terminalFont.ts:32`):

- **On** → a per-file-type icon sits next to every filename via `getFileTypeIcon(path)`
  (`src/terminal/fileIcons.ts`) — in **both** the Local Changes file list and the Log
  commit-files list. Tab / graph / stash markers also use Nerd glyphs.
- **Off** → fall back to today's `figures` pointer and plain `+/-` / `···` ASCII (no icon
  column).

Every glyph site checks the flag — a raw Nerd codepoint is never emitted unconditionally (it
renders as tofu in Alacritty/xterm). Escape hatch already exists: `CLAUDIN_NERD_FONT=on/off`.

## Log tab

- **Left** — the git graph for the last ~50 commits (HEAD), with a "load more" batch when the
  user scrolls to the bottom (`git log --skip`/`-n`). Each row: graph rail + short hash
  (`permission` blue) + author + subject, with decorations before the subject. Theme colors
  differentiate at a glance: each **author** gets a stable color from the shared 8-entity palette
  (`entityColor`, hashed by name in `entityColor.ts`), **tags** render green (`success`, `tag: `
  prefix stripped), and **branches/HEAD** render amber (`warning`). The selected row stays a
  single uniform inverse line (no nested colors).
- **Project selector (monorepo).** When more than one repo is in scope (the same set the Local
  tab groups), a `project: <name> ▾   [ ] project` line sits above the graph and `[`/`]` cycle
  which repo's log is shown. `logRepoIndex` selects from `workspace.groups`; switching resets the
  selected commit row and points both the graph (`useGitLog(logRoot)`) and the commit-files pane
  (`CommitFileList cwd={logRoot}`) at that repo. `useGitLog` reloads from the top whenever its
  `cwd` changes. Single-repo workspaces show no selector.
- **Right** — the selected commit's changed files (icon + per-file `±stats`), with the
  **commit-wide `+added −removed` totals** right-aligned on the pane border (same `statsBorderText`
  the Local diff pane uses; summed across the commit's files via `useCommitFiles`). The list is a
  **selection**, not just a scrollable list: `↑/↓` move the highlight (`u/d` page, `g/G` ends) and
  `Enter`/`→` drill into that file's diff — the third level.
- **Per-file commit diff (level 3).** The selected file's hunks render in the same pane through the
  same windowed `DiffPane`/`renderDiffRows` path the Local tab uses, so theme colors, word-diff and
  syntax highlighting are identical; the border shows `Diff: <path>  N-M/total` and that file's
  `+added −removed`. `←` (or `Esc`) steps back one level at a time — diff → files → commits — and
  `Esc` at the top closes the overlay. Data comes from `fetchCommitDiff` (`git show -p --format=
  --src-prefix=a/ --dst-prefix=b/ <hash>` → `parseGitDiff`, the same map shape as the working-tree
  and stash sources) via `useCommitDiff`, which fires **only once the user drills in** — moving
  through the log still costs one `--numstat` call per commit — and keeps the last commit's patch so
  re-entering it is instant. No file text is fetched for a historical commit, so `··· N lines` gap
  collapsing is off there and the hunks render verbatim, like `git show`; binary files and
  content-less renames fall back to a message.
- **Footer status line** — `main ↑2 ↓1 · 12 changed` on **both** tabs: branch + ahead/behind +
  dirty count, from `getBranch` / `getAheadBehind` / `getFileStatus` (`src/vcs/git/git.ts`). It
  tracks the repo currently in view — the selected Log project on the Log tab, otherwise the cwd
  repo — by passing that repo's root to each of the three queries.

Two ways to draw the rail, documented for the implementer:

1. **Let git draw it** — `git log --graph --decorate --format=<delimited>` and keep git's rail
   glyphs (`* | / \ _`), mapping selectable rows to commit lines. Simplest, exact topology.
   **Recommended for v1.**
2. **Lay out the rail ourselves** — parse parents (`--format=%H %P …`) and render lanes, so we
   can swap in Nerd glyphs / per-lane theme colors. More code, prettier — a follow-up.

## Empty / no-repo states

- **Local Changes** clean → `Working tree is clean` (as today).
- **Log** → still lists commits.
- **Outside a git repo** → both tabs show `Not a git repository`; the overlay still opens.

## Refresh

The working tree changes while the overlay is open (the agent edits files). Data is fetched
lazily (working tree on mount; log on first Log activation; stashes on first stash selection) and
`r` forces a manual refresh — there is no focus-regain or periodic auto-refresh, to avoid flicker
and extra git I/O. `r` re-fetches the working tree, the log (Log tab), and the stash list +
active-stash detail, resets the collapse/expand state, and returns the diff scroll to the top.

## How it works (design)

### Layout & focus

- Left column = fixed ~36-col `Box`; right pane = `flexGrow={1}`. The right pane wraps content in
  a scroll viewport (`scrollTop` clamped to content height; `↑/↓` ±1, `PgUp/PgDn` ± viewport
  height) — active only when focus is `'content'`.
- **Narrow terminals**: when `useTerminalSize().columns < 100`, fall back to today's stacked
  `viewMode: 'list' | 'detail'` path (keeps small terminals usable, reuses existing components).

### Tab system

Uses the **inline `/agents` pattern** (`src/agent/ui/agents/AgentsMenuWithTabs.tsx:41-52`): a
`Box` row of `<Text inverse={activeTab === …}>` for the tab bar plus `useInput` for `Tab`
switching — *not* the shared `design-system/Tabs`. Trade-off: the inline bar provides no
built-in header↔content focus or scroll, so the focus model and the right-pane scroll viewport
are **hand-rolled** in `DiffDialog`.

### Components (future PR — not built in this round)

- `src/vcs/diff/ui/DiffDialog.tsx` — becomes the shell: inline tab bar, tab state
  (`'local' | 'log'`), hand-rolled focus (`'list' | 'content'`), keybindings, footer status line.
- `src/vcs/diff/ui/DiffFileList.tsx` — reused; gains group headers + icon column.
- `src/vcs/diff/ui/DiffPane.tsx` — the **collapsible** detail pane (it replaced
  `DiffDetailView.tsx`, deleted in PR #72): inserts `··· N lines` markers around
  `StructuredDiff` hunks and a scroll viewport.
- **new** `src/vcs/diff/ui/CommitGraph.tsx` — the graph/tree rail.
- **new** `src/vcs/diff/ui/CommitFileList.tsx` — per-commit changed files.
- **new** `src/vcs/hooks/useGitLog.ts` + `fetchGitLog` (in `src/vcs/git/gitDiff.ts` or `git.ts`).
- **new** `src/vcs/hooks/useGitStashes.ts` + `fetchGitStashes`.

## Suggested rollout (phases)

1. **Split + collapse/expand** — turn list/detail into the side-by-side Local Changes tab with
   scroll and the `··· N lines` markers. (Reuses everything; biggest UX win, lowest risk.)
2. **Log tab** — add the graph (git-drawn, approach 1) + per-commit file list + footer status
   line.
3. **Sources** — fold per-turn into the source selector and add stashes.
4. **Multi-repo grouping** — thread the repo-root parameter through `fetchGitDiff*` and group the
   list per project.
5. **Polish** — Nerd-Font icons, `gg` shortcut, narrow-terminal fallback, approach-2 graph
   renderer.

Evolve `DiffDialog` in place (no feature flag); each phase ships independently.

## As-built deltas

Where the implementation refined the study (all decided with the user before building):

- **The split layout is fullscreen-only; scrolling is not.** The side-by-side layout renders
  only when fullscreen (`isFullscreenEnvEnabled()`) **and** `columns ≥ 100`; otherwise the
  stacked list↔content path renders on both tabs. That gate used to cover the scroll paths too,
  which left the stacked path with an unbounded body and every scroll key inert — it dumped the
  whole diff past the top of the terminal with no way to move it. Both layouts now render the
  same windowed body (`DiffPane` on the Local tab, a windowed `CommitFileList` on the Log tab)
  and share the scroll keys; the stacked path grows a header row standing in for the pane
  border's title + `N-M/total` readout, paid for out of the body's height budget
  (`bodyHeight = contentHeight - 1`).
- **Responsive sizing.** Left pane width is `clamp(30, round(columns × 0.30), 50)` (capped so
  ultra-wide hands space to the diff); list/scroll windows track `rows`. Re-layouts live on
  resize via `useTerminalSize()`.
  The stacked (non-split) path is sized from the terminal too: the file list gets the same
  `contentHeight - 2` window as the diff body it stands in for — a fixed 15 rows both wasted a
  tall window and overflowed a short one — and its width is capped at `INLINE_LIST_WIDTH` (80)
  so the right-hand badge column (binary/large/renamed) stays next to the file names instead of
  being stranded at the far edge of a wide terminal.
- **Diff scrolling is a manual row-pager, not `ScrollBox`.** `ScrollBox`'s
  viewport culling only clips inside a real alt-screen fullscreen root; in
  inline / main-screen-rewrite mode (e.g. Ghostty via `shouldUseMainScreenRewrite`,
  where `isFullscreenEnvEnabled()` is true but the overlay still renders in the
  scrolling transcript) it renders every child row, so a tall diff grew the
  whole dialog. The diff body now pre-renders to final wrapped rows
  (`DiffPane.renderDiffRows` → `ColorDiff.render()` returns the same `string[]`
  `StructuredDiff` feeds to `RawAnsi`) and windows them to a fixed height; the
  dialog owns the scroll offset (↑/↓ line when the diff has focus, PgUp/PgDn
  page, g/G ends, clamped), so the frame is bounded in every render mode while
  keeping theme colors / word-diff / syntax highlighting.
- **Page keys are `u`/`d`, not PgUp/PgDn.** PgUp/PgDn only reach the dialog inline. In
  fullscreen the REPL mounts `ScrollKeybindingHandler`, whose Scroll-context
  `scroll:pageUp`/`scroll:pageDown` handlers always consume and `stopImmediatePropagation()`
  before any dialog's `useInput` runs — so the footer advertised a key that had never worked in
  the split layout. `u`/`d` are unbound elsewhere and reach the dialog in every render mode;
  PgUp/PgDn stay wired as a synonym for where they do arrive. (`/explorer` has the same
  constraint and uses `ctrl+d`/`ctrl+u` for a half page.)
- **Fixed-height frame.** Because the overlay is NOT mounted in a
  constrained-height root, both panes are pinned to a constant
  `height = contentHeight + 2` and the left pane is `flexShrink={0}` +
  `overflow:hidden`. Otherwise the dialog height tracked the selected file's
  diff length: a short diff shrank it and a tall one grew it past the viewport,
  pushing the tab bar off the top. `contentHeight = rows - 12` reserves the
  10-row chrome budget and a 2-row safety margin. The budget is 10 (not 8)
  because the Dialog lays out `[title, sourceLine, body, footer]` in a column
  with `gap={1}` BETWEEN every child — on the Local tab the extra `sourceLine`
  and its surrounding gaps cost 2 rows the Log tab doesn't, which is why the
  Local footer used to clip while the Log footer fit.
- **Navigation.** `←/→` move focus between the list pane (Files/Log) and the
  diff/content pane; `↑/↓` navigate the list when it's focused and scroll the
  diff when the diff is focused (`u`/`d` page, `g`/`G` ends). The same keys page
  the list itself when the list has focus. On the Log tab they act on the graph
  (paging lands on a commit row, never a graph continuation row) or on the
  selected commit's file list, whichever has focus. `[`/`]` cycle the
  Local Changes source (working tree / session turns / stashes) — relocated off
  `←/→` so the arrows can drive pane focus. New `diff:focusList` /
  `diff:focusContent` actions; source cycling kept the `diff:previousSource` /
  `diff:nextSource` action names.
- **Theme-faithful diff.** The diff body renders through `StructuredDiffList`/`StructuredDiff`
  (the same `useTheme()` → `ColorDiff` path the transcript "Update(…)" uses); the whole reviewer
  resolves colors from theme keys, so `/theme` recolors it like the rest of the CLI.
- **Collapse interaction.** Collapsed by default; `Enter` (focus on content) grows the next
  collapsed gap ±10, `a` toggles whole-file expand. Expansion feeds context-extended hunks to
  `StructuredDiff`; fails open for non-working-tree sources and binary/large/deleted files.
- **Sources × repos.** Per-project grouping applies to the working-tree source only; per-turn and
  stash sources reflect the cwd repo. Source data is fetched lazily (log on first Log activation,
  stashes on first stash selection). The source selector is a single `source: <name> ▾` line.
- **Scope.** Roots = cwd repo + `/add-dir` workspace dirs + nested child repos discovered under
  those bases (`findNestedGitRoots`), deduped by canonical path.
- **`gg` is a buffer-level chord**, not a keybinding (a `g` then a quick second `g` on an empty
  prompt), so it never swallows the first `g` of a typed word.
- **Framing/footer.** Two titled bordered panes (active pane border uses a theme accent); a
  one-row footer with the status line left and key hints right.
- **Commit files debounced** (~150ms after the selection settles); **refresh** re-fetches every
  source, resets collapse/expand and the diff scroll to top, and clamps the selection into the
  new row range — it deliberately does **not** remap the selection by path (that fought normal
  up/down navigation: the index snapped back on every move).
