    fix(providers): retry transient 404s from OpenAI-compat providers
    
    OpenAI-compat providers sometimes return transient 404s (model loading,
    routing blip). Previously these were treated as permanent failures,
    causing unnecessary fallback to non-streaming or outright errors.
    
    - shouldRetry() now retries 404s with [openai_category=...] marker up
      to 2 attempts, excluding model_not_found (model genuinely missing)
    - claude.ts excludes model_not_found from non-streaming fallback too
    - Uses extractOpenAICategoryMarker() instead of duplicated regex
    - Add MACRO global to 4 test files broken by getClaudinUserAgent()
    - Add 5 shouldRetry tests for 404 retry logic
