commit 53b6c6d319cd1664a5b577e619d85307df08738d
Author: Viudes <dev@example.com>
Date:   Mon May 4 21:11:03 2026 -0300

    fix(interrupt): propagate Ctrl+C to exit handler when nothing to cancel (#12)
    
    CancelRequestHandler's handleInterrupt consumed every app:interrupt
    event without returning false, so useKeybinding called
    stopImmediatePropagation() unconditionally. In long sessions, after
    the first Ctrl+C aborts a task, React hasn't re-rendered yet — the
    stale isCtrlCActive closure still shows true, so the handler fires
    again on the second Ctrl+C and swallows it. The double-press-to-exit
    handler (useExitOnCtrlCD) never sees the keypress.
    
    Fix: handleInterrupt now reads abortSignal.aborted and
    hasCommandsInQueue() fresh (not from stale closures) and returns
    false when nothing was cancelled, allowing the event to propagate
    to the exit handler.
